# 实时行情快照同花顺主链路改造设计

## 目标

修复首页“红绿家数 / 强势板块 / 昨日强势追踪”在东方财富实时接口失效时退回到 5 月 28 日或 5 月 29 日收盘后本地历史的问题。

改造后的目标状态：

1. 红绿家数优先使用同花顺供应商市场总览口径的实时结果。
2. 强势板块优先展示同花顺热点题材归因聚合后的真实题材。
3. 当同花顺热点题材不可用时，回退到同花顺行业板块 HTML 总览。
4. 当同花顺行业板块也不可用时，再回退到东方财富实时板块榜。
5. 只有前面全部失败时，才回退到本地历史分组结果。
6. 修复后发布桌面端 `1.0.0`，同步 git tag 和 GitHub release 版本。

## 背景与根因

当前实现的实时链路主要依赖：

1. `Sina` 指数实时接口。
2. 东方财富 `push2` 板块榜。
3. 东方财富 `push2` 全 A 实时涨跌统计。
4. 本地 `Warehouse` 历史日线兜底。

实测结果显示：

1. `Sina` 指数接口仍然可用。
2. 东方财富 `push2` 概念榜、行业榜、全 A 实时涨跌统计在当前环境下都被远端直接断开连接。
3. 因此 `breadth` 返回 `null`，`strong_sectors` 返回空数组。
4. 前端最终只能显示指数实时，红绿家数和强势板块退回本地历史或直接空白。

同时，对 `simonlin1212/a-stock-data` 的对照验证说明：

1. 同花顺热点题材归因接口当前可用，且不需要登录态。
2. 同花顺旧的 `ajax/1` 行业板块列表接口当前返回 `401`，不能再继续直接使用。
3. 但同花顺行业板块和行业资金流页面本身仍是服务端渲染 HTML，分页页也可直接抓取。
4. 因此同花顺行业总览仍可作为稳定回退源，只是抓取方式要从旧 AJAX 改成 HTML 解析。

## 方案选择

本次采用如下主备链路：

### 1. 红绿家数

主源：

- 同花顺供应商市场总览口径。

回退：

- 东方财富全 A 实时涨跌统计。
- 本地 `Warehouse` 最近交易日统计。

取舍：

- 用户已明确接受供应商市场总览口径，不要求逐只股票明细实时聚合。
- 这样可以避免在东方财富不可用时继续卡回本地历史。

### 2. 强势板块

主源：

- 同花顺热点题材归因接口。

回退 1：

- 同花顺行业板块 HTML 总览。

回退 2：

- 东方财富概念榜。

回退 3：

- 东方财富行业榜。

回退 4：

- 本地历史分组。

取舍：

- 强势板块优先展示“题材”，不是大盘分组，也不是伪造的市场前缀分组。
- 当题材源拿不到时，再回退到行业总览，保证界面仍然有稳定可读的强势方向。

### 3. 昨日强势追踪

继续保留本地历史主逻辑，但增加与新主榜体系的衔接：

1. 若今日主榜来自同花顺题材，则昨日强势追踪优先基于昨日题材聚合结果计算。
2. 若题材聚合无法获得昨日数据，则回退到同花顺行业总览的昨日口径。
3. 最后才退回当前本地 `Warehouse` 分组结果。

目标：

- 保留“昨日强势延续”的判断能力。
- 避免继续出现“创业板 / 沪市主板”这类伪板块名称。

## 数据源设计

### 同花顺热点题材归因

接口：

- `http://zx.10jqka.com.cn/event/api/getharden/date/{date}/orderby/date/orderway/desc/charset/GBK/`

用途：

1. 获取当日强势股列表。
2. 读取 `reason` 字段作为题材归因。
3. 对 `reason` 做题材拆分、归一化和频次统计。
4. 结合涨幅、换手、成交额、出现次数生成题材热度榜。

输出：

- `SectorMover[]`，其中 `name` 为真实题材名，`source` 为 `ths-hot-reason`。

### 同花顺行业板块 HTML 总览

页面：

- `https://q.10jqka.com.cn/thshy/index/field/199112/order/desc/page/{page}/`

备用页面：

- `https://data.10jqka.com.cn/funds/hyzjl/field/tradezdf/order/desc/page/{page}/`

用途：

1. 抓取同花顺行业涨跌榜。
2. 读取行业涨跌幅、上涨家数、下跌家数、领涨股。
3. 在题材榜失败时作为“强势板块”回退结果。

说明：

- 明确不再使用 `ajax/1` 旧接口。
- 统一采用 HTML 解析方式，避免继续撞上 `401`。

### 同花顺市场总览

用途：

1. 解析供应商市场总览中的上涨家数、下跌家数、平盘数。
2. 生成 `MarketBreadth`，`source` 标记为 `ths-market-summary`。

说明：

- 口径允许为供应商市场总览，不要求逐只股票明细聚合。
- 若同花顺总览解析失败，再退回东方财富全 A 统计。

## 题材聚合规则

### 输入

同花顺热点题材接口中的每条记录包含：

1. 股票代码。
2. 股票名称。
3. 题材归因字符串 `reason`。
4. 涨幅、换手、成交额等字段。

### 处理

1. 将 `reason` 按 `+`、`/`、`、` 等分隔符拆开。
2. 清理空串、泛化词、过长营销词。
3. 对明显同义词做归一化。
4. 按出现次数、平均涨幅、总成交额综合排序。
5. 输出前 N 个题材作为强势板块主榜。

### 约束

1. 不把“创业板”“沪市主板”“深市主板”当作题材。
2. 不把全市场大类标签伪装成强势题材。
3. 归一化字典使用最小必要集，先修正最常见的重复表达，不做大规模 NLP。

## 返回消息文案

消息文案需要更精确反映真实来源，例如：

1. 指数来自 `Sina`，红绿家数来自同花顺市场总览，强势题材来自同花顺热点题材归因。
2. 强势题材不可用时，明确说明已回退到同花顺行业板块总览。
3. 只有最终退回本地历史时，才说明“昨日强势追踪来自本地历史”或“红绿家数来自本地历史”。

目标是让前端底部来源说明与真实链路一致，不再误导。

## 测试设计

### 后端单元 / 接口测试

新增测试覆盖：

1. 同花顺热点题材接口成功时，`strong_sectors` 来自题材聚合。
2. 题材聚合失败时，回退到同花顺行业 HTML 总览。
3. 同花顺市场总览成功时，`breadth` 来自供应商市场总览。
4. 同花顺失败、东方财富成功时，仍能回退到东财。
5. 同花顺和东方财富都失败时，最终回退本地历史。
6. 返回消息中的 `source` 和 `message` 与实际链路一致。

### 回归测试

保留并适配现有：

1. 东方财富概念榜优先测试。
2. 东方财富行业榜回退测试。
3. 本地历史昨日强势追踪测试。

这些测试需要根据新的优先级重新调整断言。

## 风险与边界

1. 同花顺页面 HTML 结构未来可能变动，因此解析函数要做字段容错。
2. 同花顺热点题材是编辑归因口径，适合作为“强势题材提示”，不适合被误解为交易所官方分类。
3. 供应商市场总览口径与逐股统计口径可能存在细微偏差，但用户已接受此口径。
4. 本次不引入浏览器自动化抓取，也不引入登录态、`hexin-v`、JS 签名方案，避免把桌面端实时模块变成高维护组件。

## 决策摘要

本次不继续硬攻同花顺被封的旧 AJAX 接口，而是切换到当前仍可稳定访问的同花顺 HTML 页面和热点题材接口。

这符合三个目标：

1. 实时性优先。
2. 强势题材优先。
3. 在东方财富失效时仍能稳定展示可读结果。
