# Astock Backtester v1.3.5 Release And Cleanup Design

## Goal

Publish the realtime and saved-strategy correctness fixes as desktop version 1.3.5, remove the superseded full-array saved-strategy mutation interface, and clean obsolete local installer artifacts without deleting historical GitHub releases, installed application files, required sidecars, or user data.

## Scope

The release includes the already committed fixes from `929620c` and a patch-version bump from 1.3.4 to 1.3.5.

Version fields must remain aligned across:

- `package.json`
- `package-lock.json`, including the root package entry
- `pyproject.toml`
- `backend/astock_backtester/__init__.py`
- `src-tauri/Cargo.toml`
- `src-tauri/Cargo.lock`, for the workspace package
- `src-tauri/tauri.conf.json`

## Deprecated Interface Removal

The frontend production path now uses `upsert_saved_strategy` and `delete_saved_strategy`. The old full-array mutation interface is no longer needed and will be removed:

- Rust Tauri command `persist_saved_strategies`
- its registration in the Tauri invoke handler
- frontend helper `persistSavedStrategiesToStore`
- comments and tests that treat the old command as an available persistence path

The load command remains. Browser localStorage persistence remains because it is the non-Tauri implementation, not the deprecated desktop mutation interface.

Removal is complete only when repository-wide reference search finds no production or test reference to `persist_saved_strategies` or `persistSavedStrategiesToStore`, and the full test suites still pass.

## Required Programs

The following files are required runtime components and must not be deleted:

- `astock-data-service.exe`
- bundled `node.exe`
- `ths-cookie-worker.cjs`
- `xhr-sync-worker.js`
- the installed desktop executable and uninstaller

No program will be deleted merely because it is large. A file must have both zero build/runtime references and an identified replacement before it can be classified as unused.

## Local Installer Cleanup

Cleanup is limited to local files under:

`src-tauri/target/release/bundle/nsis`

The existing 1.3.1, 1.3.2, 1.3.3, and 1.3.4 installer executables and matching `.sig` files will be deleted only after the new 1.3.5 installer and signature have been built and verified. The final local NSIS directory should retain only the 1.3.5 installer and its matching signature.

The cleanup does not include:

- GitHub historical releases or their assets
- `运行产物` installed application files
- strategy configuration or local market data
- signing keys
- development tools or required build inputs

## Build And Signing

The release uses the existing project signing key through process-local environment variables. The key and password must never be printed, committed, written to reports, or included in logs.

The sequence is:

1. Build and verify the Python sidecar and companion Node resources.
2. Run the signed Tauri NSIS build for version 1.3.5.
3. Confirm the installer and `.sig` are newly generated by this build.
4. Compare packaged sidecar/resource hashes with the workspace build inputs where the existing release procedure requires it.
5. Generate `release-assets/latest.json` from the real 1.3.5 signature using `scripts/write-latest-json.ps1`.
6. Validate the JSON version, URL, ASCII release asset name, and non-empty signature.

If signing or packaging fails, no GitHub Release is created and the old local installers remain available.

## Verification

Before publishing:

- Python full test suite
- frontend full test suite
- TypeScript typecheck
- Vite production build
- Rust library tests
- `build:data-service`
- changed-file Ruff comparison against the current commit baseline
- `git diff --check`
- version-alignment tests
- repository-wide deprecated-interface reference search

The installed-package probe must cover the endpoints and NDJSON behavior required by `AGENT必读.md`. It must use the packaged sidecar rather than a development Python process.

## GitHub Release

After all verification succeeds:

1. Commit and push the 1.3.5 release changes on `codex/realtime-crawler-api-stability`.
2. Create annotated tag `v1.3.5` at the verified release commit and push it.
3. Create a non-draft, non-prerelease GitHub Release.
4. Upload the installer as `Astock-backtester_1.3.5_x64-setup.exe` and upload `latest.json`.
5. Download or query the uploaded assets and verify their sizes/digests and updater metadata.

The release notes will summarize realtime timeout/single-flight correctness, strategy persistence concurrency and validation, and architecture/test improvements.

## Failure Handling

- Do not publish partial or unsigned updater assets.
- Do not reuse an old `.sig` or `latest.json`.
- Do not delete the prior local installer set until 1.3.5 has passed build and signature verification.
- Do not modify token, CORS, or API exposure boundaries unrelated to removal of the superseded local Tauri command.
- Keep `.workbuddy/memory` files untracked and outside every commit.
